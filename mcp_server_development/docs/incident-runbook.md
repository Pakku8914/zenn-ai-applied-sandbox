# MCP サーバー インシデント対応 Runbook（社内ドキュメント検索）

**この文書は事故の最中に読むものです。前提の説明は最後に置いています。**

## 0. 最初の 3 分でやること

1. 状況を 1 行で記録する（時刻・何を見て気付いたか・誰が対応しているか）
2. 下の判定表で「失効が必要か」「停止が必要か」を決める
3. 決めたことを記録に追記する（判断の履歴が事後レビューの材料になる）

| 見えている症状 | 失効 | 停止 | 最初に見るもの |
| :--- | :--- | :--- | :--- |
| トークンがログ・コミット・チャットに出た | 必要 | 不要 | 該当トークンの発行元 |
| `findings` のアラートが出た（汚染文書の疑い） | 不要 | 不要 | `findImpact({ directiveId })` |
| `parent_traversal` / `symlink` が急増 | 不要 | 状況次第 | アクセス元と `subject` |
| エラー率が 5 分間 5% 超 | 不要 | 状況次第 | `summarizeAuditLog` の `byReason` |
| 別テナントのデータが見えたとの報告 | 必要 | **必要** | セッションとテナントの対応 |

## 1. トークンを失効させる

| 項目 | 内容 |
| :--- | :--- |
| やること | 認可サーバー側で revoke → 新トークンを発行 → 環境変数を差し替え → 再起動 |
| 判断基準 | 「漏れた可能性がある」で実行する。「漏れた証拠がある」まで待たない |
| 担当 | 認可サーバーの管理者（不在時は当番） |
| 飛ばしてよい条件 | 秘密情報が関与していないと**断定できる**とき |
| よくある失敗 | ログを削除して満足する。ログはすでに複製されているので削除では止まらない |

## 2. サーバーを止める

| 項目 | 内容 |
| :--- | :--- |
| やること | ホスト側の設定からサーバーを外す／コンテナを停止する／配布経路も止める（npm の `deprecate`、イメージタグの撤去） |
| 判断基準 | 被害が**拡大中**か。すでに終わった事象なら止めずに調査を優先する |
| 担当 | サーバーの運用担当 |
| 飛ばしてよい条件 | 影響が読み取り専用の範囲にとどまり、拡大しないと判断できるとき |
| よくある失敗 | 動いているプロセスだけ止めて、配布物（`npx` で取得できる版）を放置する |

## 3. 影響範囲を特定する

| 項目 | 内容 |
| :--- | :--- |
| やること | `findImpact(lines, { directiveId })` → 出てきた `sessionRef` で `findImpact(lines, { sessionRef })` → 期間・テナント・対象を確定 |
| 判断基準 | 「誰の」「いつから」「何に対して」が言えたら完了 |
| 担当 | 調査担当（監査ログへの読み取り権限が必要） |
| 飛ばしてよい条件 | **なし。** 範囲を言えないまま再開してはいけない |
| よくある失敗 | 生値が無いから追えないと諦める。`subject` と `sessionRef` の参照値で追える |

## 4. 原因を修正し、テストで固定する

| 項目 | 内容 |
| :--- | :--- |
| やること | 修正 → 同じ事故を検出するテストを追加 → `vitest run src/session15` と `verify-injection.ts` が通ることを確認 |
| 判断基準 | 「修正前のコードでそのテストが落ちる」ことを確認できたか |
| 担当 | 実装担当 |
| 飛ばしてよい条件 | **なし。** テストのないパッチは再発する |
| よくある失敗 | 修正だけしてテストを足さない。次の担当者が同じ場所を壊す |

## 5. 再開と再発防止

| 項目 | 内容 |
| :--- | :--- |
| やること | **アラートを 1 本足してから再開する**（今回の症状を最初に捉えられる指標） |
| 判断基準 | 同じ事象が次に起きたとき、人間の気付きより先に通知が来る状態か |
| 担当 | 運用担当 |
| 飛ばしてよい条件 | **なし。** 「今回も人が気付いた」なら何も学べていない |
| よくある失敗 | 行動が決まっていないアラートを足す。通知は無視されるようになり、本当に危ないものも埋もれる |
