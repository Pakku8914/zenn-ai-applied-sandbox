# グラフ導入の判断メモ（みなと商事 社内ヘルプデスク検索）

- 作成日: 2026-08-15
- 判断者: 検索担当
- 測定条件: 2026-08-15 実測 / aarch64 / CPU 2コア / メモリ 5.8GB / Python 3.12.13
- 対象: `corpus/docs.jsonl`（301文書）／`corpus/queries.jsonl`（120クエリ）＋ 本章で定義したマルチホップ質問3件

## 1. 結論

**GraphRAG は導入しない。** 参照追跡（多段検索）で同じ答えに届き、事前構築と更新の仕組みを持たずに済むため。
再評価は **2026-11-15**（3か月後）。再評価のトリガーは下の「4. 見直す条件」に置く。

## 2. 質問型の分布（何が解けていないか）

| 質問型 | 件数 | 上位10件で解けるか | 主因 | 打ち手 |
| :--- | --: | :--- | :--- | :--- |
| keyword / natural / temporal | 78 | 解けている | — | 現状維持 |
| abbrev | 20 | 解けていない | 到達不足 0.592 | 同義語（S05・S10。グラフでは直らない） |
| multi_condition | 12 | 半分 | 順位不足 0.495 が支配的 | リランク（S09。グラフでは直らない） |
| unanswerable | 10 | 黙るのが正解 | — | abstention（S11） |
| マルチホップ（本章で定義） | 3 | 解けない | 語彙が1つも重ならない | 参照追跡 or グラフ |

複数条件クエリを「グラフ案件」と決めつけないこと。候補には入っている（Recall@100 0.947）ので、順位の問題である。

## 3. 抽出できた関係と、その正味の価値

| 項目 | 値 |
| :--- | --: |
| 参照名の辞書 | 115 項目（157 文書） |
| 本文から拾った言及 | 255 件（うち参照先が絞れないもの 120 件 = 47%） |
| エッジ（link=all） | 375 本（related 156 / mentions 216 / delegates_to 3） |
| **テーマ（語彙のかたまり）をまたぐエッジ** | **3 本（0.8%）** |
| 構築コスト（ルールベース） | LLM 呼び出し 0 回 |
| 構築コスト（LLM 抽出・1文書1回） | 301 回。テーマをまたぐエッジ 1 本あたり 100.3 回 |
| 維持コスト（直近の改訂 36 文書） | 再抽出 36 回＋参照名の全体再解決 |

372 本は同じテーマの中のリンクで、語彙が重なるため通常の検索でも届く。**グラフで初めて届くのは 3 本ぶんだけ。**

## 4. 代替策との比較

| 方式 | マルチホップ3問 | 事前構築 | 更新 | 質問時のコスト |
| :--- | :--- | :--- | :--- | :--- |

| 参照追跡（多段検索） | 3/3 | 不要 | 不要 | 追加の検索1ラウンド |
| 参照グラフ（delegates_to 1ホップ） | 3/3 | 必要 | 文書改訂のたび | 辞書引きのみ |

## 5. 見直す条件（どれか1つでも満たしたら再検討する）

1. マルチホップでしか解けない質問が、クエリログの上位100件のうち **10件以上**になったとき（現在は3件）
2. 「この規程を参照しているのはどれか」という**逆方向**の問い合わせが運用に必要になったとき（参照追跡では答えられない）
3. 追加の検索1ラウンドがレイテンシ予算（S09 で決めた 500ms）を超えたとき
4. 参照の書き方が揺れて、ルールベースの抽出漏れが **10%** を超えたとき（LLM 抽出の検討に入る）

しきい値の 10件 / 10% は運用上の判断値であり、測定値ではない。四半期ごとに実績で置き換える。

## 6. いま入れる打ち手

- 参照追跡を検索パイプラインの2段目に入れる（`delegates_to` に見える表現＝「別に定める」「に従う」を含む文だけを対象にする）
- リンク切れ検査（書式から拾った参照名が辞書で解決できるか）を索引更新のジョブに入れる
- 集約質問はメタデータ集計で答える経路を用意する（検索に投げない）
